A rookery is not rebuilt each spring. It is added to — one stick at a time, by whoever is carrying one.

Why the rook

Seven tools over one endpoint

Share speaks MCP at /mcp with a bearer token. An agent that can call tools can post a finished artifact without knowing anything about your storage, your host or your DNS. Posting is private. A share link is a separate step.

share_post
Post files as an artifact. Stays private. Returns the artifact URL.
share_create_link
Mint an expiring /s/… URL so someone without an account can open it.
share_list
List artifacts in the caller’s space.
share_get
Get one artifact by name.
share_delete
Move an artifact to trash.
share_restore
Restore an artifact from trash.
share_whoami
Return the authenticated identity.

Or one command

The share CLI does the same three-step upload the API does — declare the manifest, put the blobs, commit the version.

$ share post ./build --title "Q3 margin review"
Posting build  (14 files)

https://share.c52.com/q3-margin-review

It refuses to post files that look like secrets unless you pass --force-secrets.

Private until you say otherwise

Nothing is public by default

A posted artifact is visible to its owner. There is no “anyone with the link” state you can fall into by accident.

Links expire

Create a link with a TTL, a label and an optional password. Revoke it and it stops resolving immediately.

Unknown and unauthorized are the same 404

A wrong URL and a URL you may not see return identical responses. The difference is not observable from outside.

Served with the headers on

Every artifact response carries a content security policy, nosniff, noindex and a strict referrer policy.

What it is instead of

  • A Netlify or Vercel drop A deploy target, with a build and a project to configure
  • GitHub Pages A branch, a commit and a repository per thing you publish
  • A zip file in an email Nothing to open at the other end
  • A Dropbox or Drive link A file download, not a page
  • A screenshot in Slack Not the artifact

Each of those was built for something else first. Share does one thing: take finished files from a machine and return a URL that a person can open.

Run it yourself

git clone https://github.com/iXanadu/ShareWeb.git
cd ShareWeb
pip install -e ".[dev]"

cp examples/.env.example .env
cp examples/.keys.example .keys      # fill in the two secrets
sharectl bootstrap --email you@example.com --handle you

uvicorn server.main:app --port 8000

You sign in with a passkey. Agents get bearer tokens you issue and revoke from the dashboard. Everything is stored on your own disk and in your own Postgres.
